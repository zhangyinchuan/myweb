# Backend Requirements: 个人网站

## Context

这是一个综合型个人网站，面向普通大众访客。前端使用 Next.js 14（App Router + ISR），后端使用 Strapi v4 作为 Headless CMS。站长通过 Strapi 后台管理所有内容，访客只读浏览，无需登录。

网站分四大模块：**首页**、**博客**、**视频分享**、**书籍分享**。所有内容都有分类和标签，支持筛选浏览。

本文档描述前端需要什么数据，以及用户能做什么——具体 API 结构、字段命名、端点设计由后端决定。

---

## Screens / Components

---

### 1. 全局配置（所有页面共享）

**Purpose**: 每个页面都需要渲染导航栏、页脚，以及 SEO meta 信息。这些数据来自站点全局配置，全站只有一份。

**Data I need to display**:
- 站点名称（用于导航栏 logo 文字、浏览器标签页标题）
- 站长头像（导航栏或 Hero 区）
- 一句话简介（首页 Hero 区展示）
- 各社交媒体链接（GitHub、微博、B站等，页脚展示）
- 联系邮箱（页脚展示）
- 页脚版权文字
- 默认 SEO 标题和描述（作为各页面 SEO 的 fallback）

**Actions**:
- 访客点击社交链接 → 在新标签页跳转到对应平台（纯前端处理，无需后端）

**States to handle**:
- **正常**：全局配置存在，渲染导航和页脚
- **缺失**：如果配置不存在或字段为空，前端需要能优雅降级（隐藏该元素，而不是报错）

**业务规则**:
- 全局配置是单例，始终只有一份，不存在列表场景
- 社交链接可能部分为空（站长不一定有所有平台账号），前端需按需渲染

---

### 2. 首页（`/`）

**Purpose**: 网站入口页，展示个人品牌 + 最新内容动态，引导访客进入各内容模块。

**Data I need to display**:

*Hero 区：*
- 站长名字
- 一句话简介
- 头像图片（含适配不同尺寸的版本，用于响应式显示）
- 社交媒体链接列表（同全局配置）

*最新博客预览区（展示最新 3-6 篇已发布文章）：*
- 每篇文章的标题
- 封面图（含缩略图版本）
- 摘要（约 100-150 字的简短描述）
- 发布日期
- 所属分类的名称
- 标签列表（名称即可）
- 文章的访问路径标识（用于生成跳转链接）
- 预估阅读时长

*最新视频分享区（展示最新 3-6 个已发布视频）：*
- 每个视频的标题
- 缩略图（含适配尺寸的版本）
- 所属平台（B站 or YouTube，用于显示对应平台图标）
- 发布日期
- 视频的访问路径标识（用于跳转详情页）

**Actions**:
- 点击博客卡片 → 跳转到对应博客详情页（前端路由）
- 点击视频卡片 → 跳转到对应视频详情页（前端路由）
- 点击「查看全部博客/视频」按钮 → 跳转到对应列表页（前端路由）

**States to handle**:
- **Loading**：页面首次构建时拉取数据（ISR，60s revalidate）
- **Empty**：某个区块暂无已发布内容时，隐藏该区块或显示占位提示
- **部分数据缺失**：封面图为空时显示默认占位图，摘要为空时不渲染摘要区

**业务规则**:
- 只展示状态为"已发布"的内容
- 按发布时间倒序排列，取最新的 3-6 条（具体数量可商议）

---

### 3. 博客列表页（`/blog`）

**Purpose**: 展示所有已发布博客文章，支持按分类或标签筛选。

**Data I need to display**:

*筛选栏：*
- 博客模块下所有可用的分类列表（名称 + 标识符，用于筛选操作）
- 所有已被至少一篇文章使用的标签列表（名称 + 标识符）

*文章卡片列表：*
- 标题
- 封面图缩略图
- 摘要
- 发布日期
- 所属分类名称
- 标签列表
- 阅读时长
- 文章访问路径标识

*分页信息：*
- 当前页文章总数
- 是否还有更多文章（用于"加载更多"或翻页）

**Actions**:
- 点击分类 → 筛选出该分类下的文章（URL 参数变化，重新请求）
- 点击标签 → 筛选出含该标签的文章（URL 参数变化，重新请求）
- 点击文章卡片 → 跳转详情页
- 加载更多 / 翻页 → 获取下一批文章

**States to handle**:
- **Loading**：筛选条件变化时的加载状态
- **Empty**：当前筛选条件下没有文章，显示"暂无内容"
- **Error**：数据拉取失败，显示错误提示并提供重试
- **筛选叠加**：分类和标签可以同时选中（是否支持多选标签，请后端确认）

**业务规则**:
- 只展示已发布内容，按发布时间倒序排列
- 筛选分类和标签时，结果取交集（同时满足）

---

### 4. 博客详情页（`/blog/[标识符]`）

**Purpose**: 展示单篇博客文章的完整内容。

**Data I need to display**:
- 标题
- 封面图（原始尺寸）
- 封面图的 alt 文本（无障碍访问）
- 发布日期、最后更新日期
- 所属分类（名称 + 标识符，可点击跳转列表页）
- 标签列表（名称 + 标识符，可点击跳转列表页）
- 阅读时长
- 正文内容（富文本，包含段落、标题、图片、代码块、链接、列表等）
- 上一篇 / 下一篇文章的标题和路径标识（用于文章底部导航）

**Actions**:
- 点击分类/标签 → 跳转到对应筛选结果的列表页
- 点击上一篇/下一篇 → 跳转对应文章

**States to handle**:
- **Not Found**：文章不存在或未发布，显示 404 页面
- **Loading**：ISR 构建期间的状态
- **图片加载失败**：正文内图片加载失败时显示 alt 文本

**业务规则**:
- 未发布（draft/archived）的文章对访客不可见，返回 404
- 上一篇/下一篇按发布时间相邻计算

---

### 5. 视频列表页（`/videos`）

**Purpose**: 展示所有已发布的视频推荐，支持按分类或标签筛选。

**Data I need to display**:

*筛选栏：*
- 视频模块下的分类列表
- 已被使用的标签列表

*视频卡片列表：*
- 标题
- 缩略图
- 所属平台（B站 / YouTube）
- 简短描述（约 80-100 字）
- 发布日期
- 视频时长（如有）
- 标签列表
- 视频访问路径标识

**Actions**:
- 按分类/标签筛选视频
- 点击卡片跳转详情页
- 加载更多 / 翻页

**States to handle**:
- **Loading / Empty / Error**：同博客列表页

---

### 6. 视频详情页（`/videos/[标识符]`）

**Purpose**: 展示单个视频的完整信息，并嵌入视频播放器。

**Data I need to display**:
- 标题
- 视频嵌入所需的标识信息（用于生成 B站/YouTube iframe，具体格式由后端提供）
- 所属平台（决定使用哪种 iframe 模板）
- 完整视频链接（作为 iframe 加载失败时的降级跳转链接）
- 简介（富文本或纯文本）
- 发布日期
- 视频时长
- 分类和标签（同博客详情页逻辑）

**Actions**:
- iframe 内嵌播放视频（前端处理）
- iframe 加载失败时 → 展示"点击跳转原平台观看"的降级按钮
- 点击分类/标签 → 筛选跳转

**States to handle**:
- **Not Found**：视频不存在或未发布，返回 404
- **嵌入失败**：B站/YouTube 加载失败（网络问题），显示降级跳转按钮

**业务规则**:
- B站和 YouTube 的 iframe embed URL 格式不同，后端需提供足够信息让前端判断使用哪种模板（`platform` 字段 + `embed_id` 字段）
- 未发布视频对访客不可见

### 7. 书籍列表页（`/books`）

**Purpose**: 展示所有已发布的书籍推荐，支持按分类、标签、评分筛选。

**Data I need to display**:

*筛选栏：*
- 书籍模块下的分类列表
- 已被使用的标签列表
- 评分选项（1-5 星，用于按评分筛选）

*书籍卡片列表：*
- 书名
- 作者
- 封面图（竖版，书籍封面比例）
- 简评（约 100 字）
- 评分（1-5 星）
- 标签列表
- 书籍访问路径标识

**Actions**:
- 按分类/标签/评分筛选
- 点击卡片跳转详情页
- 加载更多 / 翻页

---

### 8. 书籍详情页（`/books/[标识符]`）

**Purpose**: 展示单本书的完整信息和读书笔记。

**Data I need to display**:
- 书名
- 作者
- 出版社（可选）
- 出版年份（可选）
- ISBN（可选，展示用）
- 封面图（较大尺寸）
- 评分（1-5 星）
- 简评
- 读书笔记全文（富文本，可能包含引用、分级标题、图片等）
- 分类和标签
- 发布日期（即读书笔记的发布时间）

**Actions**:
- 点击分类/标签 → 跳转筛选列表页

**States to handle**:
- **Not Found**：书籍不存在或未发布，返回 404
- **笔记为空**：读书笔记字段为空时，仅展示书籍基本信息，不渲染笔记区块

## Uncertainties

- [ ] 标签筛选是否支持多选？（同时选中多个标签，取并集还是交集？）
- [ ] 分页采用传统翻页（page 1, 2, 3）还是「加载更多」（cursor-based）？每页多少条合适？
- [ ] 博客/书籍的富文本格式是 Strapi Blocks JSON 还是 Markdown 字符串？前端需要知道用哪种渲染器
- [ ] 图片 URL 是直接返回阿里云 OSS CDN 的完整 URL，还是相对路径需要前端拼接域名？
- [ ] 上一篇/下一篇文章数据是单独请求，还是随文章详情一并返回？
- [ ] ISR revalidate 的 60 秒策略是否足够？还是需要 Strapi 在内容发布时主动触发 Next.js 的 `revalidatePath`？
- [ ] 视频的 `embed_id` 是否已经是可以直接拼入 iframe src 的值，还是需要前端做额外处理？
- [ ] 书籍的评分筛选：是精确匹配（只看 5 星）还是范围过滤（4 星及以上）？

## Questions for Backend

- 富文本内容（博客正文、读书笔记）的数据格式是什么？建议在示例 API 响应中包含一个真实的富文本字段示例，方便前端选择合适的渲染库
- 媒体文件（封面图）是否提供多尺寸版本（缩略图 / 中等 / 原图）？如果有，格式是什么样的？前端可以根据不同场景选用不同尺寸，减少流量
- 分类和标签的数据，是跟随每条内容一起返回（嵌套），还是需要单独请求？如果是单独请求，筛选栏的数据应该怎么获取效率最高？
- 内容列表是否支持按发布时间以外的维度排序（比如书籍按评分排序）？还是固定只按时间倒序？
- Strapi 的 API 是否默认对媒体 URL 做了处理（返回完整的 OSS CDN 地址）？还是需要前端自己拼接域名？
- 对于 Next.js ISR，是否考虑配置 Strapi webhook，在内容发布时主动调用 Next.js 的 revalidation API？这样可以避免 60 秒延迟，内容发布后立即生效
